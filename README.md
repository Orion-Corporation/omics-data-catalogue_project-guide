## Project Overview

The Omics Data Catalogue project provides a catalogue for omics data at OrionPharma. This guide is the central place for project instructions for end users and developers.

![Omics Data Catalogue](pictures/Omics_Data_Catalogue.png)

*Overview of the Omics Data Catalogue architecture*

- **(1) Data Source**. Omics data are stored in Domino Research within project folders, each following a standardized subfolder structure.
- **(2) Omics Data Annotation**. Omics data are labelled by users through the _Omis Data Label_ web application.
- **(3) Sync to Data Model**. A scheduled Job exports Omics metadata files to the Ressu Databricks Lakehouse.
- **(4) Omics Data Model** Omics Metadata Files are ingested to the Omics Catalog data model.
- **(5) Omics Data Catalogue**. The Omics Data Catalogue web application enable users to query the catalogue.

## User Guide

The Omics Data Catalogue is primarily intended for the **Bioinformatics team at Orion Pharma**. This section describes the typical workflow for onboarding omics data, annotating it, and finding it in the catalogue.

The end-to-end workflow is:

**Create a project folder → Add omics data → Create metadata → Automatic synchronization → Search the catalogue**

### QA and PROD environments

Two environments are available:

- **QA**: used for experimentation, testing new features and ideas, and gathering feedback from users.
- **PROD**: the operational environment used for omics data supporting real Bioinformatics analysis.

Users are encouraged to experiment freely in the **QA** environment. The **PROD** environment is more restricted, and manual intervention should generally be avoided.

The same workflow described below applies to both environments, with the appropriate Domino Storage Unit selected when creating the project folder.

### 1. Create a project folder in Domino

Omics data are stored in project folders on Domino Storage Units. Currently, the following Domino Netapp Volumes are used:

- `BIOINFO_data_lake` — PROD environment
- `bioinfo_data_lake_QA` — QA environment

Project folders must be created using the **Create Datasets Folders** Domino Launcher. The Launcher automatically creates the project folder together with the required subfolder structure.

To create a project folder:

1. Access Orion Pharma's Domino deployment: https://orion.domino.tech/home
2. Navigate to the **BIOINFO_data_lake** Domino project.
3. Select **Deployments → Launchers**.
4. Open the **Create Datasets Folders** Launcher.
5. Select the target NetApp Volume where the project folder should be created:
   - `BIOINFO_data_lake` for PROD.
   - `bioinfo_data_lake_QA` for QA.
6. Click **Run**.

The Launcher creates the project folder and its required subfolders automatically. No further action is required to create the folder structure.

> **Important:** Only project folders created using the **Create Datasets Folders** Launcher are included in the Omics Data Catalogue. Manually created folders are not recognized as valid project folders and will not be included in the catalogue.

### 2. Add and organize omics data

Once the project folder has been created, omics data can be added to the appropriate subfolder.

Each project folder contains the following standard subfolders:

| Subfolder | Purpose |
|---|---|
| `raw_data` | Raw omics data |
| `processed_data` | Results generated by Bioinformatics analysis |
| `metadata` | Metadata files used to annotate the omics data |

Raw omics data should be placed under `raw_data`. Results generated during Bioinformatics analysis should be stored under `processed_data`.

Metadata files generated using the **Omics Data Label** application must be stored under the `metadata` subfolder.

The standard project folder structure should not be modified. Only valid project folders following the expected structure are included in the Omics Data Catalogue.

### 3. Annotate omics data using Omics Data Label

After the omics data have been added to the `raw_data` subfolder, metadata files can be generated using the **Omics Data Label** web application.

The application is available in both QA and PROD. Use the appropriate environment depending on whether you are experimenting/testing or working with data for real Bioinformatics analysis.

#### Generate RAW-DATA metadata

To generate metadata for raw omics data:

1. Open the **Omics Data Label** web application.
2. Select **Generate metadata for RAW-DATA**.
3. Fill in the fields in the form.
4. Click **Save YAML**.
5. Select the project's `metadata` subfolder as the destination.
6. Save the metadata file.

The `metadata` subfolder is the only valid destination for metadata files within a project folder.

#### Generate Sample metadata

Metadata for samples can be generated using the same general procedure:

1. Open the **Omics Data Label** web application.
2. Select the appropriate sample metadata option.
3. Fill in the required fields.
4. Click **Save YAML**.
5. Save the generated YAML file in the project's `metadata` subfolder.

#### Generate Processed Data metadata

Metadata for processed data can also be generated using the Omics Data Label application. Follow the same procedure, selecting the appropriate processed-data metadata option and saving the resulting YAML file in the project's `metadata` subfolder.

### 4. Automatic synchronization

Once the metadata files have been saved in the project's `metadata` subfolder, **no further action is required from the user**.

The synchronization and ingestion of metadata into the Omics Data Catalogue are automated.

The expected synchronization times are:

- **QA:** approximately **1 hour**.
- **PROD:** synchronization runs **once per day at 05:00, Helsinki time**.

Users should therefore allow sufficient time for synchronization before expecting newly onboarded data to appear in the catalogue.

### 5. Search the Omics Data Catalogue

After synchronization, users can access the **Omics Data Catalogue** web application.

The application contains two main sections:

#### Data Finder

**Data Finder** allows users to search for omics data matching specified criteria.

Search parameters can include, for example:

- Organism
- Disease Context
- Omics Modalities
- Other metadata associated with the datasets

Use Data Finder as the primary interface for discovering and locating omics data available in the catalogue.

#### Source System Status

**Source System Status** provides information about the ingestion of project folders and metadata files from the source system into the catalogue.

This section is particularly useful when a recently created project or metadata file does not yet appear in Data Finder. It provides ingestion checkpoints that can help identify whether a project folder or metadata file was rejected during ingestion and why.

### 6. Troubleshooting: data not appearing in the catalogue

If a project does not appear in the Omics Data Catalogue after the expected synchronization time, use the **Source System Status** section to investigate the issue.

#### Check the project folder

1. Open the **Omics Data Catalogue** web application.
2. Navigate to **Source System Status**.
3. Under **Project Folder**, search for the name of the project folder.
4. Check whether the project folder is recognized as **valid**.

A project folder is valid only if it follows the expected project folder structure.

If the project folder is **not valid**, this explains why it does not appear in the catalogue. Only valid project folders are included in the catalogue.

#### Check the metadata files

If the project folder is valid:

1. Navigate to the **Metadata Files** section.
2. Search for the project folder.
3. Check whether the metadata files are recognized as valid.
4. Verify that the metadata files match the authoritative metadata schema.

If one or more metadata files are invalid or do not match the authoritative schema, this identifies the likely cause of the problem.

If both the project folder and its metadata files are reported as valid, but the data still do not appear in the catalogue, contact:

**lorenzo.perino@orionpharma.com**

### 7. Important usage rules

Keep the following rules in mind when working with the Omics Data Catalogue:

- **Use QA for experimentation.** QA is the appropriate environment for testing new features, trying new ideas, and providing feedback.
- **Use PROD for real Bioinformatics analysis.** Data supporting operational Bioinformatics analysis should be handled in PROD.
- **Create project folders using the Domino Launcher.** Only project folders created with the **Create Datasets Folders** Launcher are recognized by the catalogue.
- **Follow the standard project folder structure.** Use `raw_data` for raw omics data, `processed_data` for Bioinformatics analysis results, and `metadata` for metadata files.
- **Store metadata files in the `metadata` subfolder.** Metadata files stored elsewhere will not be processed as project metadata.
- **Avoid manual intervention in PROD.** Manual changes to the PROD environment are generally not best practice and should be avoided.
